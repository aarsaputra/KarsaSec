## 1. Documentation & Code Hardening Fixes

### 1.1 Corrected Lookup Dimension Specification
- **Correction**: Updated documentation to specify **10 lookup fields**:
  `id, file, function, line, label, language, node_type, ssa_version, source_kind, sink_category`.

### 1.2 Authoritative Candidate Validation Invariant
- **File**: `karsasec/query/optimizer.py`
- **Fix**: Added validation matching `Candidates(I, predicate) ⊆ Nodes(G)`. Any candidate retrieved from `CPGIndex` is verified against authoritative `CPGGraph.nodes`. Stale/deleted nodes post-indexing are filtered out, and mutated node attributes are re-read from the graph.

### 1.3 Graph / Index Divergence Protection
- **File**: `karsasec/query/optimizer.py`
- **Fix**: Checked index size alignment (`len(index.by_id) == len(graph.nodes)`). If an index is constructed on an empty or divergent graph, the optimizer falls back to a **deterministic full scan**.

### 1.4 Call-Context Growth Bounding
- **File**: `karsasec/query/traversal_engine.py`
- **Fix**: Implemented `MAX_CONTEXT_STRING_LEN = 256` string truncation to prevent memory explosion during deep context stack propagation, while maintaining strict `(node_id, ssa_version, call_context)` state isolation.

### 1.5 Fail-Closed Bounds Protection
- **File**: `karsasec/query/traversal_engine.py`
- **Fix**: `reachability`, `bfs_reachability`, and `dfs_reachability` explicitly check for `max_depth < 0` and return `False` / `[]`, satisfying `UNKNOWN != SAFE`.
